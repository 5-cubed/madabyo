# SEQ-022 Prevent duplicate pane rendering on rapid double-split
- Status: Draft

## Requirement
REQ-022

## Components
- SplitContainer (CMP-011)
- PaneManager (CMP-009)

## Flow
<SplitContainer onSplit={sourcePaneId}>  x2 (rapid)
  |
  v
await PaneManager.splitRight(sourcePaneId)   [1st call must resolve before 2nd starts]
  |
  v
panes.length === 2 (not 4)

## Sequence
1. SplitContainer `await`s PaneManager's `splitRight(sourcePaneId): Promise<void>` and disables its own split trigger while that promise is pending, so a second click cannot issue a second call before the first resolves.
2. Internally, `splitRight()` itself awaits its own pane-list update and re-render step fully before resolving, so even a direct second call (bypassing the UI guard) cannot interleave with an in-flight first call.
3. This closes the prototype's bug where `splitRight()` called `renderPanes()` without `await`, letting two overlapping renders each clear-then-append the panes container and duplicate 2 real panes into 4 DOM elements.

## Acceptance Criteria
1. Two split triggers issued in rapid succession (e.g. within the same event-loop tick) result in `panes.length === 2`, never more.
2. The rendered pane container has exactly as many DOM pane elements as `panes.length` — no duplicated nodes.
