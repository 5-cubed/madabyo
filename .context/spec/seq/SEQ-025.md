# SEQ-025 Re-request revoked/expired permission
- Status: Draft

## Requirement
REQ-025

## Components
- WorkspaceController (CMP-001)
- FolderHandleStore (CMP-004)
- SidebarTree (CMP-005)

## Flow
WorkspaceController.resumeFolder()
  |
  v
FolderHandleStore.verifyPermission(handle) --> 'denied' | 'prompt'
  |
  v
<SidebarTree status="needs-permission" onRegrantPermission />
  |
  v
FolderHandleStore.verifyPermission(handle) [retry after user click] --> 'granted'

## Sequence
1. Before scanning a retrieved handle, WorkspaceController calls FolderHandleStore's `verifyPermission(handle): Promise<'granted'|'denied'|'prompt'>`.
2. If the result isn't `'granted'`, WorkspaceController renders `<SidebarTree status="needs-permission" onRegrantPermission={...} .../>` instead of calling `pickFolder()` or `scanTree()`.
3. When the user clicks the re-grant control, `onRegrantPermission` re-invokes `verifyPermission(handle)` (which internally calls the handle's `requestPermission()`); on `'granted'`, WorkspaceController proceeds to `scanTree(handle)` (SEQ-002) using the same handle, with no new OS picker dialog shown.

## Acceptance Criteria
1. A `verifyPermission()` result other than `'granted'` renders `status="needs-permission"`, not a silent failure or a forced `pickFolder()` call.
2. Approving the re-grant prompt scans the same handle without invoking `showDirectoryPicker()`.
